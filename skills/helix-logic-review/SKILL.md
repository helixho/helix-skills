# helix-logic-review

目标：被审查的内容里不留逻辑谬误、矛盾、重叠和缺失。依据是逻辑学四条基本规律、定义与划分规则和常见谬误；只判断推理是否成立，不评价文风、篇幅和文件位置，不核实内容所依据的事实本身。

## 范围

- 只审查用户指定的对象：一段文字、文档、方案、草案，或规则、skill 中的指令。判断关系需要其他材料时，只读与结论相关的部分。
- 判断通过与否，只以被审查文本本身、它自己规定的读取范围和用户指定的材料为依据；文本所依赖的外部事实一律标为未核实。
- 草案用标题和原句定位，不编造行号。
- 只报告问题和修正建议，不修改被审查对象，除非用户要求修改。

## 方法

1. **形式化**：规则类内容（规则、流程、指令）改写为“情境 → 动作”；论述类内容（文字、文档、方案、分析、结论）改写为“前提 → 结论”。写出隐含的前提、例外和适用范围；说不清情境、动作或前提的部分，本身就是问题。两类内容混在一起时按条款分别归类；没有推理的陈述只记下各条陈述，按四条基本规律和定义与划分检查。
2. **按四条基本规律和定义与划分检查**：两类内容都查。
3. **按类型补充检查**：规则类内容查“规则类补充”，论述类内容查“论述类补充”。规则里说明理由的句子也是论述，同样查“论述类补充”。
4. **反例**：每个问题给出一个具体情境：规则在该情境下互相矛盾、无规可依、可得出多种动作，或同时落入两个本应互斥的子项，或论述在该情境下前提成立而结论不成立。找方案的反例时，可先假设方案已经失败，倒推最可能导致失败且现在就能验证的条件。举不出反例的不报；冗余与无效类问题没有这种反例，改以“可由哪条推出”或“删除后行为不变”为证据。

## 四条基本规律

1. **同一律：概念一致**。同一概念在全文用同一个词、保持同一含义；同一个词不指两个概念；“其”“该”“上述”等指代落到唯一对象；一句话不能读出两种意思，修饰和否定的范围、并列项的范围、省略的主语或宾语、多义词都要能唯一确定。中文表达重点核对：“只、先、暂时、除了、都、全部”等范围和顺序词管到哪里；一句话是疑问、建议、要求还是授权；动词是否准确（禁用不等于删除，下载不等于安装，分析不等于修改）；“拥有、维护、安装、使用、可访问”不混用；“全部”不扩大前文已确定的对象范围。违反时会出现偷换概念、歧义。
2. **矛盾律：不自相矛盾**。同一情境不能既要求做又要求不做，也不能要求两个不能并存的动作；论述中前后结论或数据不能冲突。区分用户已确认的政策替换与未决冲突：前者按确认处理；后者列出双方原句，说明取舍，由用户决定新的权限边界。
3. **排中律：不留空档**。每个情境都要落到某条规则或某个结论上，不能两边都不落；并列条件、分类和选项的完整性按“定义与划分”检查。
4. **充足理由律：结论有充分依据**。结论的范围和强度不超过依据；结论依赖的前提已写出，关键前提按现有材料标明属于有依据、待验证还是存在反证；前提不成立时结论随之失效的，要指明。

## 定义与划分

1. **划分（MECE）**：适用于一切列举、分类、并列条件和选项。每一层只用一个划分标准；子项互不重叠（互斥），条件部分重叠时即使要求的动作相同也算问题；子项合起来覆盖全部（穷尽），条件要有默认分支，选项要包括不做或维持现状，只给两个选项时检查是否漏了其他做法（虚假两难）；同一层不混入上下位概念。
2. **定义**：关键术语有定义时，定义的范围与被定义对象一致，不过宽也不过窄；不循环定义；不用比喻或含糊的词定义；能正面说明时不用否定式定义。

## 规则类补充

**单条规则**

1. **适用条件**：何时适用要能被执行者实际判断，不依赖无法观察的条件；条件不过宽也不过窄；“所有”“任何”“必须”“一律”等全称措辞，检查是否有未写明的例外。“必要”“合理”等需要判断的词，只在会导致不同动作时才算问题。
2. **主体与动作**：写明谁来做、对什么做、做什么；只写禁止的条款要补上应做的动作。
3. **完成与终止**：写明何时算完成，是否遵守可以检查；工作流中每一步依赖的输入要在之前的步骤已经产出，步骤之间不能循环依赖；“检查—修改—再检查”这类循环写明何时停止。
4. **规范强度**：必须、应当、可以、禁止等强度要能区分，不混用会被理解成不同强度的说法（比如时而“必须”时而“尽量”）；允许与禁止同时出现时，写明谁是谁的例外。
5. **实然与应然**：描述现状的句子不当作规则，也不从“现在是这样”推出“应该这样”。

**规则之间**

1. **优先级**：多条规则同时适用且结论不同时，文本写明谁优先，结果不取决于阅读顺序。修正时按特殊优先于一般、后定优先于先定、用户当前要求优先于文件写明关系。
2. **冗余与无效**：条款能从其他条款推出（冗余），或模型默认就会这样做、删掉不改变行为（无效）。冗余只保留一处；两处会导出不同动作时按矛盾处理。
3. **引用有效**：引用的章节、文件、条目或承诺的后续内容确实存在，被引用处的含义与引用方的理解一致。

## 论述类补充

1. **谬误排查**：逐一对照 [谬误清单](references/fallacies.md) 的五类谬误：形式谬误、相关性谬误、预设与证据谬误、因果谬误、歧义与类比谬误。
2. **手段达成目标**：方案把目标和手段分开，检查手段能否实现目标，是否满足目标、预算、时间和权限等约束；约束不能同时满足时明确指出。

## 输出

- 先给结论：通过，或按影响排序的问题。审查多个对象时，先按对象分组列出问题，再按影响汇总排序。
- 每个问题写明违反的规律、规则或谬误名称、原句与位置、反例情境和修正，并标明是文字修正，还是会改变授权、工作方式或结论。
- 修正写成可直接替换原句的改写，用常用词和通行说法，不用迂回的描述。修正需要补充依据才能成立时，写明需要补充什么，不编造依据。
- 论述推不出结论时，写“依据不足以支持”，不判定结论为假。
- 修正后对改动处用同样的检查复查一轮，确认没有引入新问题；仍有问题的列出交给用户，不再循环。自己提出的修正和替代方案适用同一标准。
- 没有问题就报告通过，不为凑数量制造问题。
- 逻辑审查不能证明规则会被实际遵守，也不能证明前提为真；未做行为实测或事实核实时明确说明。
