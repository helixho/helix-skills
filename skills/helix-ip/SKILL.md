# helix-ip

品牌 IP 只回答"是什么、对谁、怎么说、往哪个方向看"。设计系统回答"长什么样、怎么实现"。

## 边界

- **产出**：每个品牌一份 `IP.md`，只保存当前结果。不写过程、版本、审批、讨论记录。
- **不包含**：Logo 设计意图、变体、审批状态、主稿来源；token、组件、页面、预览门户。Logo 和视觉资产以设计系统中的文件与说明为准。
- **与环境无关**：不假设文件放在哪里，不依赖任何知识库、仓库、脚本或运行时。用户给出已有文件就读取；没有指定保存位置时，在对话中输出完整内容，由用户决定存放。
- **输入**：对话、文字材料、图片、URL、已有文件。图片和参考只作为线索，不照搬他人品牌。

## 流程

**建立或更新 IP.md**

1. 读取用户提供的现有 `IP.md` 和材料。
2. 按 [ip-template.md](references/ip-template.md) 整理。事实只收两类：用户明确确认的、材料中直接可见的。其他内容放进"待确认"，不写进正文。
3. 只追问会改变定位、口径或视觉方向的缺口，一次问最少的问题。
4. 输出完整的当前版本：直接替换旧内容，不追加修改记录；已解决的待确认项直接删除。
5. 按 [review-checklist.md](references/review-checklist.md) 的"IP.md 自检"部分检查后交付。

**审查设计系统、页面或物料**

1. 需要用户提供 `IP.md` 和被审查对象（链接、文件或截图）。
2. 按清单"对外产物审查"部分逐项对照。
3. 列出每处冲突：位置、原文、问题、建议改为。不自行修改被审查对象，除非用户要求。

## 结论格式

给出一个判断和最小下一步：

- **可用**：没有冲突，没有影响结论的待确认项。
- **可用，有待确认项**：列出待确认项和它影响的内容。
- **不可用**：列出阻塞冲突，按影响排序。

## 规则

- 不编造客户、数据、奖项、雇主、日期、资质或成果。
- 材料之间互相矛盾时列出矛盾：影响定位、口径或视觉方向的问用户，其余列入"待确认"，不自行裁决。
- 视觉方向只写选定的一个方向，不保留备选方案的比较。
- 名称、中英文写法以 `IP.md` 为准；设计系统与之冲突时，报告冲突，由用户决定改哪一边。
