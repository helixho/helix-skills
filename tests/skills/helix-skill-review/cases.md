# Skill review 综合验收案例

给审查者只提供编号与输入，AI 判卷时再提供预期。各例前提已给定，无需联网。
检查实际依据、建议取舍及是否越界；不按评分高低、问题数量或措辞一致性判通过。
可用 helix-logic-review 的案例工具准备与汇总；该工具不是本 skill 的运行时依赖。

### C01

#### 输入

Skill 的 validate 通过，所有文内链接存在。但用户要求它处理单篇和批量任务，源码明确只处理单篇，没有批量入口或转交说明。请评估。

#### 预期

保留结构检查通过的事实，同时报告批量能力缺口；建议依据用户需要补能力或明确转交，不把 lint 通过写成整体可用。

### C02

#### 输入

目标 Skill 明确只用于用户的个人本机工具。lint 找到工具的本机目标路径，用户无公开发布要求。没有证据表明路径被用于定位 skill 自身资源，目标配置也正确。

#### 预期

区分业务目标路径与开发机资源依赖，不仅凭路径存在就扣可移植性分或要求改成公开通用工具。

### C03

#### 输入

本例已给官方证据：当前宿主支持一个扩展字段，但它不属于通用 Agent Skills 规范。Skill 声明只用于该宿主，字段类型正确。lint 报告“宿主扩展警告”。

#### 预期

说明这是通用规范之外的宿主扩展，在指定环境有效，不能直接判为无效配置或要求删除；若讨论跨宿主使用，说明限制，不扩大本次目标。

### C04

#### 输入

评估目标是帮助用户减少重复劳动。现有小脚本满足全部已给任务，有相应检查。用户明确偏好简单本地工具，没有服务部署需求。候选建议是将它拆成三个常驻服务，因为这样“更成熟”。

#### 预期

不把复杂架构当成熟度，要求说明真实收益和维护代价；在已给证据下建议保留现有设计，不能为了提高分数强行重构。

### C05

#### 输入

一份评分报告的引用文件和行号都存在，分数范围正确，报告结构校验通过。但引用原文是“每次请求独立处理”，发现却称该原文证明“请求之间必然共享状态”。没有其他依据。

#### 预期

指出引用不能支持发现，撤回或修正该发现及关联建议；不能把报告结构通过等同于证据与推理正确。
