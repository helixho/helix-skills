# 逻辑审查验收案例

这是验收数据，不是 skill 的运行时参考。各例独立，输入中已给定的事实作为该例前提；不要求外部事实检索。语境也是输入的一部分，不得为隐藏答案而删掉。

## 验证方法

- 旧版与新版分别使用独立上下文、相同模型设置和相同任务提示。只提供各例的编号与“输入”，不提供分组、预期、另一方输出或既有评审结论。
- 要求逐例给出判断、依据和必要的最小修正，标明修正是否改变事实、目标或政策。没有依据的问题不得为了凑数而报告。
- 按下面已经写明的依据核对漏报、误报和修正越界，不以问题数量多少评分，也不要求措辞或谬误标签完全相同。
- 失败时修正对应条款，重测受影响的案例；保留实际分歧，不通过删掉案例或放宽预期让新版通过。单次对照只说明这些案例中的表现，不代表普遍准确率。
- 运行记录留在任务工作目录，不提交生成的评测报告。

## 应报告

### C01

#### 输入

同一份报告必须在本周三中午 12:00 前提交，同时不得在本周三下午 14:00 前提交。两条要求同时有效，没有例外或优先级。

#### 预期

报告两项要求不能同时满足。给出同一提交时间无法同时落入两个区间的依据。不能擅自改时间或决定哪项优先，应指出需要澄清的要求。

### C02

#### 输入

所有诗歌都属于文学作品。这篇作品属于文学作品，因此它一定是诗歌。

#### 预期

报告肯定后件：属于文学作品不足以推出属于诗歌。可构造其他文学作品的反例，或说明缺少反向包含关系。不得为修复结论而凭空补入“所有文学作品都是诗歌”。

### C03

#### 输入

小林告诉小周，他的申请已获批准。没有其他上下文说明“他”指谁。

#### 预期

报告“他”可能指小林或小周，申请归属不清。即使没有执行任务，也应指出歧义。建议明确指代，不替作者选定申请人。

### C04

#### 输入

本文将分别介绍方案甲、乙、丙。正文全部内容为：方案甲适合短期使用；方案乙适合长期使用。

#### 预期

报告缺少原文承诺的方案丙介绍。以承诺与正文对照为依据，不要求先证明执行失败。建议补充已有资料或调整承诺，不编造方案丙的特点。

### C05

#### 输入

这是一段只保留事实、没有强调用途的简短摘要：会议定于周五举行。会议的举行日期是周五。

#### 预期

报告两句信息重复，建议保留一处或合并。不能因不影响结论或执行而略过，也不能据此断言删去重复会改变或不会改变模型行为。

### C06

#### 输入

本段用途是给出“充分”的判定标准。全部定义为：充分就是已经足够充分。

#### 预期

报告循环定义或空泛解释，没有提供承诺的判定标准。建议提供独立、可理解的依据或说明尚缺信息，不擅自添加数值门槛。

### C07

#### 输入

用户要求只整理会议中已经通过的决定。正文为：会议决定下周试用新流程。我更喜欢绿色的衣服。会议未讨论服装或颜色。

#### 预期

报告个人颜色偏好与指定整理范围无关，建议移除该句。无需证明它改变了会议决定，也不评价该偏好本身。

### C08

#### 输入

已知本月网站改版，报名人数也增加。除此没有给出因果证据。结论是：报名人数增加必然由改版造成。

#### 预期

报告同期变化不足以支持必然因果结论。不否定两项观察事实。可保留观察、说明因果待核实，或提出待检验假设；不能只添加“可能”就声称已经建立因果依据。

## 不应误报

### C09

#### 输入

本规则只列两个独立触发条件，未声称对文稿作互斥分类：缺标题的稿件需要补充标题；缺摘要的稿件需要补充摘要；两项都缺少时补齐两项。

#### 预期

不因条件可以同时成立而报错，不要求改成互斥分支。共同触发时动作明确且相容，两条要求也不是相同信息的重复。

### C10

#### 输入

下面仅举两种练习方式：复述文章、改写短句。练习方式还有其他种类，本段不负责列全。

#### 预期

不因未穷尽所有练习方式而报告遗漏。这里是明确限定的举例，不是声称完整的分类。

### C11

#### 输入

本条只限制删除行为：禁止删除原始合同。它不规定合同保管流程。

#### 预期

不强制补充保管、备份或其他正向动作。局部禁令本身完整，不因未描述整体流程而报缺失。

### C12

#### 输入

本规范将提交申请的人称为“申请人”，也称“提交者”，两词指同一角色。申请人提交表格后，提交者可查询进度。

#### 预期

不因同时出现两个词而报告概念不一致。别名关系已明确；不能把统一词语的编辑偏好当作逻辑错误。

### C13

#### 输入

目标是把段落按编号升序排列。可以手工整理，也可以使用工具，实现方法由执行者选择；两种方式都必须得到同样的升序结果。

#### 预期

不把已授权的实现选择当成歧义或缺少优先级。用户已经要求完成排序，不强制增加“不整理”选项。

### C14

#### 输入

在生产过程和随机抽样方式未改变的前提下，过去独立随机抽取的 10,000 件产品中有 9,900 件合格。使用样本合格率 99% 作为总体合格率的暂时估计；这有抽样误差，不保证单件结果。

#### 预期

不以“下一件仍可能不合格”为反例否定暂时估计，不把它读成确定保证，也不无条件要求增加文本未承诺的完整统计报告。

### C15

#### 输入

给定事实：专业档案员已将目录与本次指定的全部材料逐项比对，确认没有遗漏。本文据此认为目录在这个指定范围内完整；没有据其名气作判断，也不据此断言材料内容真实。

#### 预期

不因引用专家意见就判为诉诸权威。前提给出了相关领域和直接核对依据，结论也限定了范围；不要求用户重新证明本题已经给定的事实。

### C16

#### 输入

本文只给出定义：非会员指当前没有有效会员资格的人。

#### 预期

不因采用否定表述而报告定义错误。该表达清楚划定了所定义概念的范围，没有循环或含混。

## 修正与判断不能越界

### C17

#### 输入

给定且不得改写的系统行为：允许开机联网、开机但不联网，以及关机。待审查文字为：系统有且仅有两种模式，开机且联网、关机。

#### 预期

报告分类遗漏，优先补入“开机但不联网”。不得通过禁止离线开机或改写给定行为来保住原来的两类划分。

### C18

#### 输入

总则要求所有申请获负责人批准后才能执行。较晚写的附则要求紧急申请未经批准直接执行。两条都被要求继续生效，未声明例外、替代或优先级，用户也未决定取舍。

#### 预期

报告紧急申请场景下的要求冲突，提出需要确定的政策。不得仅凭附则更新或更具体，就决定它已经覆盖总则；若提供替代文本，应标明各方案如何改变政策。

### C19

#### 输入

同一提示的两处“只输出 JSON”表达相同约束。只用三个例子比较过删前删后，两边都输出了 JSON。因此在任何任务中删除重复提示都不会影响行为，它绝对无效，应当删除。

#### 预期

报告由有限测试推到任何任务的依据不足。可以确认文本重复，以及三个例子中未观察到格式差异；不能据此证明普遍无效。允许讨论文本维护价值，不要求为了本次审查继续做行为测试。

### C20

#### 输入

用户只要求审查规则正文：“按申请编号升序列出本次全部申请。”关联说明仅用于理解记录格式：“每份申请具有唯一编号；导出脚本偶尔失败。”本次不审查导出脚本。

#### 预期

规则正文无已知逻辑问题。不得把关联说明中的脚本可靠性问题列为这条规则的缺陷，也不得将审查对象扩展到脚本实现。
